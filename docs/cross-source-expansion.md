## 如何使用不同来源

旅行编辑网站用于发现街区、文化体验、地方菜肴和住宿线索；旅游局、文化机构、景点及酒店官网用于交叉核对实体、位置和访问条件。无法实际读取的网页不记为已查阅来源，不将多个域名自动等同于彼此独立的事实核验。中文介绍重新撰写，原文中的排名、宣传语和个人点评不当作客观结论。

新条目通过 `sourceReferences` 保存参考资料的名称、网址、类别、用途和查阅日期。景点、食物、住宿的完整资料及城市速览展开后可查看这些链接，主卡仍保持紧凑。查阅日期表示读过这份资料，不表示核实了某日票价、菜单价格或可售房态；费用核验继续使用独立的 `price.type`、`checkedAt` 和报价来源。

地区资料见 [中国来源](china-cross-source.md)、[日本与韩国来源](asia-cross-source.md)、[欧洲来源](europe-cross-source.md)。食物保留当地名称与寻找区域；住宿包含不同位置和类型，城市住宿预算不能代替具体酒店报价。

## 维护

- 新城市：`data/expansion/*-cross-source.json`。
- 已有城市的人工小地点：`data/place-expansion/*-editorial.json`，与地图采集包分别维护，导入保留项目 ID。
- 食物和住宿：`data/food-expansion/*-cross-source.json`、`data/experience-expansion/*-cross-source.json`。
- `npm run audit:catalog` 同时检查来源元数据结构，并汇总具备参考资料的项目、不同主机名和不重复链接数量；这些是资料记录统计，不是线上可用性或价格核验结果。
- 图片使用已确认主题与许可的文件，缺少合适实拍时保留明确标注的插画。抓取和较小缩略图维护见 [图片维护](images.md)。

新城市提供编辑推荐天数，主题乐园、整日远郊、预约和季节活动按各自限制维护，不把开放历史或旅行网站旧攻略当作当前入场保证。新增机场门户也使用现有交通预留机制；跨城市、跨海岛的移动继续占用实际行程空间。
