# 街区、慢游与特色食物

2026-09-23 扩充了 27 座目的地，其中中国 16 城、国外 11 城。中国新增城市包含重庆、济南、郑州、海口、三亚、万宁、陵水、厦门、青岛、大理、丽江、桂林、洛阳、泉州、南京和苏州，每城维护 10 个地点或体验。国外新增布莱德、科托尔、戈佐、帕福斯、丰沙尔、蓬塔德尔加达、甲米、兰塔岛、龙目岛、亚庇和纳克索斯。

## 人工目录与地图补充

香港人工目录从 6 项增加至 40 项，包括旺角、油麻地、中环、迪士尼、女人街、油麻地旧警署、重庆大厦、花墟、金鱼街及街市。原有地点 ID 保留；旧项目可以继续使用。

人工地点提供特色、坐标、完整推荐时长、最短与最长游览建议、费用口径和来源。按 `visitRole` 区分主要去处、短街区与按兴趣选择的项目。`automaticPlanning:false` 的项目只在用户明确选择后安排，并不表示它不值得去。

地图补充库独立存于 `data/place-expansion/`。它收集参考中心周围 6 公里的具名公共街巷、街区、市场、公园、展馆等，每城最多 30 项；保留实际来源和抓取日期。它不是穷尽全世界所有地点的数据库，地图标签也不等于已经核验开放、门票与导航入口。详细范围、ODbL 许可和维护命令见 [地点库说明](place-library-sources.md)。

## 自动安排

- 主要活动优先，短街区沿已有路线补充，考虑午后实际可用时间，并保留推荐游览时长。三餐、交通、抵达与返程窗口仍参与同一时间计算。
- 休闲目的地通常每天精选至多 2 个主要活动；短街区不占主要活动名额。海滩午后等长体验不会被压成短打卡。
- 原有手动日程保持不变。工作台的“补充附近小去处”会把可自动安排的零门票短街区放入候选，重新计算后可以撤回。
- 用户明确选择的地点优先；容纳不下的选择保留并提示。普通地点尚未排入时不计门票，而已选供应商体验即使待安排，仍在预算中保留。
- 明确选择迪士尼等整日地点，且当天没有跨城占时，可以在不跨午夜的条件下安排至 12 小时。普通自动精选仍限制为 8 小时活动负荷；手动超时会提示。
- 城市选择篮生成可能为已选内容延长最多 14 天，国家规划仍遵守给定总天数。两种入口的时间约束不同。

## 特色食物

`data/local-foods.json` 维护 205 种食物，关联全部 127 座详细目的地，每城至少 2 种。包括中文名、当地名称、介绍、吃法、按城市区分的寻找区域或具名餐厅，以及资料来源。

城市页“美食”分为“特色食物”和“餐厅与套餐”。特色食物用于了解和寻找当地味道，属于原有日常餐费预留，不重复计费。区域检索是寻找起点，不保证任何特定店铺供应该食物。具名餐厅关联有单独出处，但仍需核对当前菜单。

照片从相应食物或地点的公开摄影中选择，保留 Commons 作者、许可证及拍摄日期。无法准确匹配时使用名称与图标，不用城市风景或原材料照冒充成品。部分食物使用所属食物类别的实拍；不同地方的做法与摆盘可能不同。

## 持续维护

```powershell
# 导入人工目的地和增量地点，保留主目录的稳定 ID
npm.cmd run import:destinations
# 合并维护的食物定义与新城市指南，保留人工编辑
node scripts/build-food-catalog.mjs
# 更新地点与食物摄影；自动跳过明确待找准确照片的条目
node scripts/fetch-images.mjs --python-network
# 校验目录结构、来源字段和缺图清单
npm.cmd run audit:catalog
```

GitHub Pages 每日维护任务最多发 6 次地点 API 请求，按 30 天缓存和来源配额逐步轮巡；普通代码发布只重用缓存，不额外采集地点。失败保留此前快照。持续采集地点不等于持续核验票价。

人工住宿与餐饮预算仍为三档估算；真实票价适配器和用户录入的报价各自保留来源口径。岛屿目的地另有门户机场与接送说明，不能把共用机场的两个岛屿视作同一座城市。
