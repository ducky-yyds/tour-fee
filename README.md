# 途算 · WAYFARER

一个可独立部署、支持中英文界面的旅行与旅居预算网页。用城市实景、可编辑的行程和逐笔核对的费用，帮助用户在出发前弄清预算。本地完整数据、SQLite 与原始资产是主版本；GitHub Pages 用于公开预览。

[在线体验](https://ducky-yyds.github.io/tour-fee/) · [GitHub 仓库](https://github.com/ducky-yyds/tour-fee) · [Pages 发布与数据维护](docs/github-pages.md)

## 运行

要求 **Node.js 24 或更高版本**（使用内置 SQLite），无需数据库服务或 API 密钥。

Windows 可双击 `start-app.cmd`，然后打开 **http://127.0.0.1:8787**。也可在当前目录执行：

```powershell
npm.cmd ci
npm.cmd run build
npm.cmd start
```

开发模式：`npm.cmd run dev`，访问 http://127.0.0.1:5173 。默认仅监听本机；前端请求通过 Vite 转发到 8787。

## 已实现

- 中英文界面：顶部切换规划、城市主页、旅居、地球、项目和数据来源的界面语言，保留行程与费用；语言偏好随个人工作区导出，也可通过 `?lang=en` 或 `?lang=zh` 分享。中文按中文名拼音排序，英文按英文名排序；支持全拼、拼音缩写与中英文名称搜索。城市卡片连续排列，桌面四列，不再按国家强制换行。已有英文名称用于展示，尚未翻译的城市介绍与来源说明保留原文。
- 城市主页：景点、独特体验、当地食物与具名住宿；卡片先展示图片、简介、金额和用时，详细服务、来源、照片署名与预约条件按需展开。城市、景点、食物及住宿的实际数量和缺口见 [目录覆盖报告](data/catalog-coverage.json)，全球候选与待补齐进度见 [目的地覆盖报告](data/destination-coverage.json)。
- 多城市与国家级规划：按城市建议天数起步，先保留去程、跨城和返程时间，再根据停留时长精选内容；支持拖动顺序、跨天移动、每处自定游览时长、自定义地点、过满与绕路提示。用户选择但放不下的内容保留为候选。
- 可比较的完整预算：住宿、餐饮、市内交通、门票、城际交通、接驳与机动费用分列；支持三档消费偏好、铁路等交通方式、不同币种、实际报价和逐项核对。所选酒店替换基础住宿预算，含餐活动扣除对应基础餐费，避免重复计费。
- 图文日程：展示有依据的活动时间、路程、三餐和住宿；未确定时刻的途中预算不显示虚构时间。城市背景轮播与地球实景让目的地更易辨认。
- 旅居生活：按月比较租金、生活账单、一次性安置费与可退押金，自定自炊比例、居住人数和住房数量；设置按城市本币保存。
- 环球探索：可旋转地球、城市照片标牌、计划路线和到访足迹；城市选择按大洲、国家组织，可搜索及按首字母浏览。默认仅展示有旅行资料的城市，历史机场节点保留用于旧存档兼容；机场名录不作为旅行内容已经齐全的证明。
- 地球地名分层：远景显示国家，中景逐步显示省州，近景显示城市；缩放切换有缓冲，标签固定在地理锚点旁，碰撞时隐藏，拖动时保留已显示标签，松手即停止转动。路线和足迹模式保留重点城市标注。地理参考标签独立于旅行城市目录，来源及更新方法见 [地图地名说明](public/maps/label-places.md)。
- 独立旅行项目：新建、复制、切换、重命名与删除，保留计划、已核对费用及自定义地点。项目 JSON、费用 CSV、足迹导出继续可用；完整个人工作区导入导出同时涵盖所有项目、活动项目、当前未保存计划、足迹与旅居偏好，便于换浏览器或域名迁移。
- 按需加载：先获取轻量城市摘要，进入城市或生成计划时加载对应详细内容；静态预览与 Node API 共用数据口径。载入旧项目会先取齐相关城市，加载失败可重试，不把未载入的景点当成已删除。
- 本地维护与归档：公开来源更新保留上次成功值；图片原件和网页派生图分开保存；完整项目快照包含 JSON 目录、SQLite 一致性备份、源代码及资产。数据质量审计与构建通过后，才可发布公共预览。

## 数据的真实范围

这版是**可使用的预算规划工具，不是全网实时预订引擎**。页面将不同数据明确分开。

| 数据 | 实际依据 | 更新方式 |
|---|---|---|
| 汇率 | Frankfurter 官方来源汇总，保留来源日期 | 自动采集 |
| 部分门票、东京地铁票 | 官方公开价，记录票种、来源及核验时间 | 已接入的适配器自动抓取，其余人工核验 |
| 具体餐饮单品 | 标注门店与来源的官方菜单 | 已实现的菜单适配器自动更新，其余人工复核 |
| 具名餐宿与活动方案 | 公开价格／菜单与编辑估算分别标记；酒店价格按预算区间或城市住宿预留展示 | 已接入的适配器更新；其余来源检查与人工复核分别记录 |
| 酒店、餐饮日均、租金 | 编辑设置的三档规划区间 | 人工维护，不是抓到的即时报价 |
| 城际交通 | 根据城市关系和所选交通方式建立的距离、时间与预算模型 | 随路线重算；铁路、飞机、船与公路均需另核真实班次和票价 |
| 用户实际报价 | 用户跳转查询后自行录入 | 用户逐项确认 |

目录区分官方票价、免费开放范围、编辑估算与费用待补充。新增地图地点没有票价资料时显示待补充，不能用零占位伪装免费。估算为 0 不等于已确认免票，免费范围也不自动覆盖展览、游乐设施或预约。菜单单品不能推导城市平均成本。景点库是持续扩充的代表性目录，不宣称完整收录世界所有地点；地图补充库的采集范围及许可见 [地点库说明](docs/place-library-sources.md)。所有来源详见 [docs/sources.md](docs/sources.md)、[全球扩展说明](docs/global-expansion.md) 与 [docs/real-price-samples.md](docs/real-price-samples.md)。

Booking 等实时住宿接口需要合作伙伴资格与密钥；机票也需要供应商授权及实际出行参数。本仓库没有这些凭据，因此没有冒充“实时最低价”。跳转预订链接不是下单操作。正式商业化时应接入获授权的供应商 API；具体要求以 [Booking 官方文档](https://developers.booking.com/demand/docs/getting-started/prerequisites) 为准。

## 预算口径

- 所有主要金额是**全体成人、整个行程的总额**；住宿按房间，餐饮与门票按人数。
- 旅行模式总晚数 = 总天数 − 1，最后一站扣除一晚。跨城交通当天仍计入该城市的停留天数。
- 独立旅居页面以 30 天标准月建立比较口径。租金、水电按住房数；饮食、交通和生活杂项按人数；日均参考转换月度预算并可自行编辑。自炊折扣为可调整的规划假设，非城市超市实测。可退押金单独列为资金占用，不加进消费总额；保险、办公、搬迁等未录入费用需补充。历史旅行项目中的旧旅居模式仍兼容，原天数/报价完整保留。
- “低—高”是当前预算假设的区间，不是全市场最低、最高价格，奢华消费不存在通用上限。
- 签证默认零元仅表示**待填写**；押金、购物、清洁费、酒店城市税、超额行李及特殊活动未自动获取。用户可调整相关明细中的总额。
- 改动人数、城市路线、日期、天数或档位会清除既有费用覆盖，并提示重新核对。仅调换景点顺序、日期、游览时长或每日开始时间会保留既有报价。增删景点只清除被移除景点的费用记录，保留酒店、航段等其他报价。消费偏好仅替换被修改类别的总额覆盖。切换显示币种会保留并换算报价；偏好单价保持目的地币种。
- 日常组包括住宿、饮食、市内交通、水电、杂费、保险和通信；固定组包括城际交通、接驳、门票和签证。固定指按次发生，不表示票价永不变化。机动预算单列，三组合计严格等于总预算，不重复计入。
- 时间线的餐饮、市内交通、门票和城际交通是现有总预算的拆分，不再重复加到总额中。跨多个交通日的同一航段与接驳只首次计费，后续注明已包含。三餐按 20% / 40% / 40% 分配；交通期间餐费作为途中餐饮预留，不另塞本地用餐时段。步行车费为零，未使用的日交通预算保留为“其他市内交通预留”。
- 交通用坐标直线距离乘绕行系数估算：步行 1.25 倍、4.5 km/h；公共交通 1.35 倍、23 km/h，再加 18 分钟接近站点及候车余量。住宿地址未填写，以城市中心坐标临时代替。它不是地图路由、实时路况或真实车票报价。
- 折返提示对比固定第一站的顺路建议，模型距离超过建议 30% 且多绕超过 3 km 才提示。实际道路、票务时间和过河条件可能改变最优选择。
- 行程均为目的地当地时间的规划草案，尚未接入实时营业时间、航班时刻、时区飞行耗时或预约余票。跨午夜显示 `+1` 并提示重新分配。
- 跨城占时使用独立可解释模型，默认在 09:00–20:30 的活动日分配，不是推算真实起飞/抵达时刻。距离、候机与接驳合计的预留超过一天时分配至多个日期；同日抵达与返程冲突时显示交通日并提示增加天数。手动填写的是实际到达市区后可开始游览、以及离开景点准备返程的当地边界；未核验时差、转机与具体班次。模型与旧缺口修复说明见 [跨城交通说明](docs/journey-transport.md)。
- 已收录的官方临时闭馆区间按具体旅行日期避开；手动排入会警示。高校等预约条件在景点说明中展示，入选不代表有预约名额。时长范围和优先级是编辑建议，不是官方承诺或用户评分；智能精选为本地可解释规则，不调用外部大模型。
- 目前只计算成人；不自动处理儿童、残障、学生、居民或 EEA 等优惠身份，页面来源说明保留适用条件。
- 汇率为参考中间价，不包括刷卡、换汇和跨境支付手续费。
- 马尔代夫邻近岛屿城际段按船程预留；国际航班查询使用 MLE 门户，马富施另列机场至岛屿接送预算。Green Tax 按人数与住宿夜数单列预留，已含税报价可将其改为 0。冰岛已收录目的地间默认公路预算。均非实时交通报价。
- 有明确通票分组的景点，同一安排日只计一张通票、跨日分别预留；多日优惠与额外进入限制仍须核对。标记的夜市建议时段不会被安排在早晨，手动时序冲突会提示。

## 数据维护

新增城市维护在 `data/expansion/`，景点补充在 `data/place-expansion/`，餐宿与特色活动在 `data/experience-expansion/`，食物在 `data/food-expansion/`。人工资料与采集结果保持可追溯来源；未知费用不能用零元代替。城市三档费用始终是规划估算，重新构建不代表重新核价。

完整本地维护需要 Python 3 及 `requirements-maintenance.txt` 中的依赖：

```powershell
py -3 -m pip install -r requirements-maintenance.txt
# 保存本地完整数据、原件与快照；不发布
npm.cmd run maintain:local
# 通过审计和构建后再提交公共内容、推送预览
npm.cmd run maintain:local -- --publish
# 不联网，只处理已有资料与归档
npm.cmd run maintain:local -- --offline
```

本机维护负责目的地发现、已接入价格来源、审核后的内容与照片、原件补下载、覆盖审计、公开来源快照和完整备份。断点与运行结果保存在 `storage/maintenance-state.json`。本机关机或断网时暂停，恢复后继续；可以把同一命令迁移到常开服务器调度。Windows 安装每日任务：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/schedule-updates.ps1 -Install -Time 07:30
```

任务需要当前账户已登录；更换项目目录后重新安装。`AUTO_UPDATE=0` 为默认，避免同时启用旧服务内更新与完整维护两个写入任务。来源 403、验证码、结构变化或解析不确定时保留上次成功值，不绕过访问控制。网页可访问只表示链接可用，不能因此更新票价核验日期。

GitHub 的每日任务仅生成来源可访问性报告；Pages 工作流只合并已提交内容、审计并发布预览，不在云端维护唯一主库或自动生成替代照片。应用测试默认为关闭，确有需要时可在手动工作流中启用。具体发布过程见 [Pages 预览说明](docs/github-pages.md)。

单独维护入口仍可使用 `npm.cmd run update:data`、`npm.cmd run import:destinations` 和 `npm.cmd run audit:catalog`。这些局部命令不能替代完整归档；资产原件、备份与正式部署说明见 [本地部署](docs/local-deployment.md)。

Node 服务从 `MEDIA_ROOT`（默认 `public/images/`）提供网页派生图，图片和清单更新后不必重建页面。可选 `VITE_MEDIA_BASE_URL` 为派生图配置 CDN，修改后需重建前端；原件目录不公开提供。照片来源与许可证见 [图片说明](docs/images.md)。

## 构建与检查

```powershell
npm.cmd run audit:catalog
npm.cmd run build
npm.cmd start
```

目录审计检查 ID、字段、图片引用与内容缺口；构建输出记录来源指纹，完整归档只纳入与当前代码匹配的服务器构建。浏览器或单元检查按改动范围选择，`npm.cmd test` 和 `scripts/smoke-*.mjs` 为可选开发检查，不会在普通预览发布中默认全部运行。

## 字体

中文优先使用本机 **华文中宋（STZhongsong）**，英文和数字统一使用 **Georgia**。已在本机浏览器核验实际使用的字体。未安装华文中宋的设备回退至系统宋体/衬线字体；仓库没有复制系统商用字体文件。金额使用等宽数字特性，方便比较。

标签、辅助说明、价格来源和地图城市名最低 12px，原 12–15px 正文上调 1px。已检查窄屏导航、卡片换行、轮播控件与地图标签避让。

## 后续上线工作

当前公共预览由 GitHub Pages 提供，正式网站可使用独立 Node 服务与持久存储。没有账号同步或在线支付，多设备共享可通过完整个人工作区 JSON 导入导出实现。进一步商业化应确定供应商授权、报价缓存期限、更多城市的事实采样流程，再增加用户账号和同步存储。不要将当前估算库宣传为实时预订价格库。
