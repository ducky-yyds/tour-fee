# 途算 · WAYFARER

一个可本地运行的中文旅行与旅居预算网页。用城市实景、可编辑的行程和逐笔核对的费用，帮助用户在出发前弄清预算。

[在线体验](https://ducky-yyds.github.io/tour-fee/) · [GitHub 仓库](https://github.com/ducky-yyds/tour-fee) · [Pages 发布与数据维护](docs/github-pages.md)

## 运行

要求 **Node.js 24 或更高版本**（使用内置 SQLite），无需数据库服务或 API 密钥。

Windows 可双击 `start-app.cmd`，然后打开 **http://127.0.0.1:8787**。也可在当前目录执行：

```powershell
npm.cmd install
npm.cmd run build
npm.cmd start
```

开发模式：`npm.cmd run dev`，访问 http://127.0.0.1:5173 。默认仅监听本机；前端请求通过 Vite 转发到 8787。

## 已实现

- 100 个目的地各自的主页（例如 `/#/city/reykjavik`、`/#/city/maafushi`）：饮食特色、街区介绍、景点选择篮、交通说明和来源。72 城提供具体餐宿与活动，共 221 个地点、449 种服务方案；其余城市尚未核验的商家分类明确显示待补充。
- 新项目、新增城市和城市选择篮采用目的地建议天数：北京、东京默认 5 天，维克 2 天，马累 1 天；所有详细目的地为 1–7 天的编辑起点。已有手动天数保留，并提供一键采用建议。仅有机场资料的地点暂定 2 天，明确资料不足。
- 首页按当前目的地轮播城市与景点实景照片，最多 6 张；底部居中透明圆点可回看，角落标摄影来源。悬停或聚焦时暂停，支持键盘和减少动画偏好。
- 新建项目或添加目的地时可切换“探索一个国家”：指定总天数，先安排城市顺序与跨城交通，再精选景点；支持手动调序、调配城市间天数、增加候选城市与绕路提示，总天数保持不变。只使用已有详细资料的城市，并明确覆盖边界；明显无法容纳交通的方案不能确认。
- 每天开始时间、已订交通的到达与返程时刻默认收在“补充细节”里，关闭仍保留填写值；交通摘要和冲突提示常显。旅行风格放在右侧预算上方，选择立即更新费用。
- 追加国家保留原有手动安排和内容未变的费用记录；原末站住宿晚数、返程或其他计费依据改变时，仅相应已录入报价恢复参考并提示重新核对。
- 环球默认仅显示 100 个有旅行资料的城市，可切换“显示全部城市”。项目路线和足迹使用完整名录；关闭全部城市时，其涉及的机场地点仅作为当前路线或足迹的必要节点保留并说明。
- 城市主页勾选后生成或更新当前项目。优先安排明确选中的餐厅、酒店和体验；必要时最多增加 14 天，只保留确实减少未排项目的天数，仍无法排入的保留候选或待安排提示。体验可在时间轴上换日、移除、返回主页改套餐。
- 具体酒店按房间和实际晚数替换住宿预算；餐厅替换对应早餐／午餐／晚餐；活动含餐扣除相应基础餐费，含接送不重复增加接送时长。固定套餐按整套容量向上取整计费，校验参与人数与套餐餐次。凌晨热气球、夜间演出保留建议时段并标明须确认。
- 59 个国家与地区、100 个目的地、821 个景点；新增冰岛、马尔代夫、北欧、东南亚、非洲、美洲与新西兰等。探索页支持洲、国家筛选和消费排序。北京保留 42 处，新增地点通常每城 8 处；数量与收录范围见 [全球扩展说明](docs/global-expansion.md)。
- 全球机场名录：实际采集 49,287 座机场、34,895 个城市或机场所在地，覆盖 239 个国家与地区。与旅行攻略去重后可搜索 34,890 处目的地，支持机场代码、国家和城市搜索、定期航班记录筛选、项目与路线规划。机场资料页提供实际机场列表、来源、官网和机票查询。详见 [机场数据说明](docs/airports.md)。
- 机场扩展城市尚未收录的食宿费用显示“待补充”，总额显示“已知费用小计”；可填写自己的住宿、饮食、交通预算或逐笔报价。扩展城市的 USD 仅为预算录入币种，不代表当地法定货币。机场位置、机场存在和定期服务标记均不表示所选日期可以直飞。
- 独立旅行项目：新建、重命名、复制、切换、删除，行程、预算、已核对费用、自定义地点各自保存；升级时迁移旧当前行程和收藏，导入文件会创建新项目。
- 选择出发地、添加及调整多站路线、停留天数、成人数、房间数、返程、出发日期。
- 跨城交通占时：去程、每次换城及返程先预留交通时间，再安排景点。长途分到多个日期；支持填写抵达后最早可活动的当地时间、抵达日在本站第几天，以及返程前最晚结束游览时间。自动计划按剩余时间精选；手动及旧存档保留内容并提示冲突，可在日程工作台使用智能重排。每段机票/城际预算与两端接驳已计入总额，也在关联日展示一次。
- 轻装、舒适、高配三档预算；45 种币种及有日期的汇率，新增本币已接入自动更新与参考快照。
- 每日图文时间线：实景、3 个特色亮点、建议时段、游览起止时间、观光时长、预计路程、交通时间、三餐预算与门票。
- 日程工作台：拖动排序、跨天移动、上下移动按钮、选择日期、每日 07:00–12:00 开始时间、增删景点及撤回上次调整。每景点可选走马观花／推荐／细致游览，也可输入 15–720 分钟；按手动安排重新生成会保留日期、顺序与时长。
- 自动精选：新建行程或改变城市停留天数时，按编辑优先级、游览时长、交通及三餐筛选可行安排。普通游览日以 8 小时活动负荷为限，扣除跨城预留后再分配本地活动，通常不晚于 20:30；长途交通日可超过 8 小时但不再追加景点。未排入的地点保留在候选清单，不收取门票预算；增加天数或点击“智能重排行程”可再安排。手动增加景点会保留选择并提示超时。
- 上述 8 小时限制针对普通景点精选；用户明确选择的全天体验最多允许 12 小时、午夜前结束，并提示繁忙或晚归。尚未安排的已选体验仍在预算中明确保留，不假装预约成功。
- 自定义地点：可录入名称、特色、游览时长、当地币种门票、可选坐标与来源链接；跟随项目保存、复制、导入导出。无坐标时明确提示无法估算该段路程。
- 超过 8 小时、深夜结束、抵达/返程日过满、明显折返提示；可主动采纳顺路建议或拆分到次日，不擅自重排用户的安排。
- 逐笔列出城际交通、食宿、市内交通、景点、两端接驳、日常杂费、保险、上网、签证占位及预备金。
- 费用分为日常成本、固定／单次成本和机动预算。住宿按每间每晚、饮食及市内交通按每人每天设置消费偏好；金额以目的地币种填写，统一换算显示币种。门票等按所选项目计算。
- 录入实际总价、标记已经核对、恢复参考值；切换币种时换算已录入金额。
- 独立旅居生活页 `/#/stay`：以月租、生活账单和长期现金需求为核心，区分按间/按人的开销、一次性安置费与可退押金；自定义月度预算、自炊比例、居住人数和房间数，比较最多三座城市。生活设置按城市原币保存，切换显示币种重新换算。
- 环球探索页 `/#/globe`：Three.js 球体使用 NASA Blue Marble 原始地表与云层纹理，搭配柔光、大气光晕；默认城市名按视角与缩放避让，悬停或轻点可看实景照片和简要信息。支持拖动旋转、惯性、缩放、键盘与触摸，关闭云层、减少动画偏好及 WebGL 不可用时的轻量地图。照片待补充的机场地点使用明确的地理示意。可浏览全球目的地、加入项目、查看路线与返程，记录到访日期与笔记、点亮地区及导入导出足迹。路线是访问顺序示意，不表示直飞航班。影像为历史卫星合成图，来源与使用说明见 [地球影像](public/maps/earth-textures.md)。
- 旅居与环球页面拥有独立的显示币种偏好；切换页面和调整生活预算不修改原旅行项目。旅行项目、生活偏好与足迹分别保存在当前浏览器。
- 酒店、交通、官方景点和地图跳转；酒店查询携带日期、人数和房间数。
- 官方餐饮菜单实例，展示具体门店及单品，独立于城市日均预算。
- 最多 50 个旅行项目自动保存在当前浏览器，JSON 导入导出、CSV 费用导出；没有云端账号同步。项目中的自定义地点最多 200 个。
- 桌面与手机响应式布局、本地实景图片、完整摄影署名与许可链接。
- SQLite 价格观察历史、来源健康状态、保留最后成功值的定时维护程序。

## 数据的真实范围

这版是**可使用的预算规划工具，不是全网实时预订引擎**。页面将不同数据明确分开。

| 数据 | 实际依据 | 更新方式 |
|---|---|---|
| 汇率 | Frankfurter 官方来源汇总，保留来源日期 | 自动采集 |
| 部分门票、东京地铁票 | 官方公开价，记录票种、来源及核验时间 | 已接入的适配器自动抓取，其余人工核验 |
| 东京、京都 8 个餐饮单品 | 4 个具体门店的官方菜单 | 部分菜单自动更新，其余人工复核 |
| 221 个具体餐宿与活动、449 种服务 | 108 个带核验日期的公开价格／菜单组合，341 个明确编辑估算；酒店均为估算 | 3 个体验适配器；其他人工复核，所有扩展包自动纳入来源链接轮询 |
| 酒店、餐饮日均、租金 | 编辑设置的三档规划区间 | 人工维护，不是抓到的即时报价 |
| 城际交通 | 直线距离分段预算模型 | 随路线重算，不代表存在直达航班 |
| 用户实际报价 | 用户跳转查询后自行录入 | 用户逐项确认 |

当前景点目录中有 45 条官方票价、23 条免费开放区域记录，另 753 条明确标为未核实估算。估算为 0 不等于已确认免票，免费范围也不自动覆盖展览、游乐设施或预约。菜单单品不能推导城市平均成本。景点库是持续扩充的代表性目录，不宣称完整收录世界所有地点。所有来源详见 [docs/sources.md](docs/sources.md)、[全球扩展说明](docs/global-expansion.md) 与 [docs/real-price-samples.md](docs/real-price-samples.md)。

Booking 等实时住宿接口需要合作伙伴资格与密钥；机票也需要供应商授权及实际出行参数。本仓库没有这些凭据，因此没有冒充“实时最低价”。跳转预订链接不是下单操作。正式商业化时应接入获授权的供应商 API；具体要求以 [Booking 官方文档](https://developers.booking.com/demand/docs/getting-started/prerequisites) 为准。

## 预算口径

- 所有主要金额是**全体成人、整个行程的总额**；住宿按房间，餐饮与门票按人数。
- 旅行模式总晚数 = 总天数 − 1，最后一站扣除一晚。跨城交通当天仍计入该城市的停留天数。
- 独立旅居页面以 30 天标准月建立比较口径。租金、水电按住房数；饮食、交通和生活杂项按人数；日均参考转换月度预算并可自行编辑。自炊折扣为可调整的规划假设，非城市超市实测。可退押金单独列为资金占用，不加进消费总额；保险、办公、搬迁等未录入费用需补充。历史旅行项目中的旧旅居模式仍兼容，原天数/报价完整保留。
- “低—高”是当前预算假设的区间，不是全市场最低、最高价格，奢华消费不存在通用上限。
- 签证默认零元仅表示**待填写**；押金、购物、清洁费、酒店城市税、超额行李及特殊活动未自动获取。用户可调整相关明细中的总额。
- 改动人数、城市路线、日期、天数或档位会清除既有费用覆盖，并提示重新核对。仅调换景点顺序、日期、游览时长或每日开始时间会保留既有报价。增删景点只清除被移除景点的费用记录，保留酒店、航段等其他报价。消费偏好仅替换被修改类别的总额覆盖。切换显示币种会保留并换算报价；偏好单价保持目的地币种。
- 日常组包括住宿、饮食、市内交通、水电、杂费、保险和通信；固定组包括城际交通、接驳、门票和签证。固定指按次发生，不表示票价永不变化。机动预算单列，三组合计严格等于总预算，不重复计入。
- 时间线的餐饮、市内交通、门票和城际交通是现有总预算的拆分，不再重复加到总额中。跨多个交通日的同一航段与接驳只首次计费，后续注明已包含。三餐按 20% / 40% / 40% 分配；交通期间餐费作为途中餐饮预留，不另塞本地用餐时段。步行车费为零，未使用的日交通预算保留为“其他市内交通预留”。
- 交通用坐标直线距离乘绕行系数估算：步行 1.25 倍、4.5 km/h；公共交通 1.35 倍、23 km/h，再加 18 分钟接近站点及候车余量。住宿地址未填写，以城市中心坐标临时代替。它不是地图路由、实时路况或真实车票报价。
- 折返提示对比固定第一站的顺路建议，模型距离超过建议 30% 且多绕超过 3 km 才提示。实际道路、票务时间和过河条件可能改变最优选择。
- 行程均为目的地当地时间的规划草案，尚未接入实时营业时间、航班时刻、时区飞行耗时或预约余票。跨午夜显示 `+1` 并提示重新分配。
- 跨城占时使用独立可解释模型，默认在 09:00–20:30 的活动日分配，不是推算真实起飞/抵达时刻。距离、候机与接驳合计的预留超过一天时分配至多个日期；同日抵达与返程冲突时显示交通日并提示增加天数。手动填写的是实际到达市区后可开始游览、以及离开景点准备返程的当地边界；未核验时差、转机与具体班次。模型与旧缺口修复说明见 [跨城交通说明](docs/journey-transport.md)。
- 已收录的官方临时闭馆区间按具体旅行日期避开；手动排入会警示。高校等预约条件在景点说明中展示，入选不代表有预约名额。时长范围和优先级是编辑建议，不是官方承诺或用户评分；智能精选为本地可解释规则，不调用外部大模型。
- 目前只计算成人；不自动处理儿童、残障、学生、居民或 EEA 等优惠身份，页面来源说明保留适用条件。
- 汇率为参考中间价，不包括刷卡、换汇和跨境支付手续费。
- 马尔代夫邻近岛屿城际段按船程预留；国际航班查询使用 MLE 门户，马富施另列机场至岛屿接送预算。Green Tax 按人数与住宿夜数单列预留，已含税报价可将其改为 0。冰岛已收录目的地间默认公路预算。均非实时交通报价。
- 有明确通票分组的景点，同一安排日只计一张通票、跨日分别预留；多日优惠与额外进入限制仍须核对。标记的夜市建议时段不会被安排在早晨，手动时序冲突会提示。

## 数据维护

新增目的地按地区维护在 `data/expansion/`，运行 `npm.cmd run import:destinations` 同步至主目录和城市指南；运行 `npm.cmd run audit:catalog` 检查 ID、坐标、币种、官方价格来源字段与缺图清单（输出 `data/catalog-coverage.json`）。图片采集器自动发现新增目的地。新增城市的人工预算不会被假装自动更新为实时报价。

立即更新所有已实现来源：

```powershell
npm.cmd run update:data
```

同一维护任务每七天刷新 OurAirports 全量名录；失败保留上次完整快照。可运行 `npm.cmd run update:airports` 立即刷新，或 `node scripts/update-airports.mjs --if-stale` 仅检查是否需要更新。机场类型过滤、同名城市分组、来源和更新状态保存在数据文件中。该更新不产生机票报价或真实航空时刻表。

更新程序也维护 Bateaux Mouches 的三种成人方案、Hero Dubai 的 Signature 成人方案、Warner Hollywood 标准成人票。2026-09-22 实测 Bateaux 与 Warner 直接采集成功；Hero 在当前 Node 网络下连接失败，埃菲尔铁塔返回 403，均保留原参考数据并记录失败。

同一次定时任务会检查最多 12 个超过 7 天未检查的商家来源链接，保存 HTTP 状态、内容哈希和人工复核队列；页面可访问不等于价格已核验，不会因此更新价格日期。人工官方价超过 30 天、来源变更或不可访问均进入复核队列。单独执行 `npm.cmd run audit:experiences` 可检查下一批，`node scripts/audit-experiences.mjs 150` 可对待检查来源做完整轮巡。说明与商家证据见 [餐宿目录](docs/city-experiences.md) 和 [活动目录](docs/city-activities.md)。

## 字体

中文优先使用本机 **华文中宋（STZhongsong）**，英文和数字统一使用 **Georgia**。已在本机浏览器核验实际使用的字体。未安装华文中宋的设备回退至系统宋体/衬线字体；仓库没有复制系统商用字体文件。金额使用等宽数字特性，方便比较。

标签、辅助说明、价格来源和地图城市名最低 12px，原 12–15px 正文上调 1px。已检查窄屏导航、卡片换行、轮播控件与地图标签避让。

本轮新增 131 个条目的逐项来源与价格边界见 [亚洲非洲扩展](docs/experience-expansion-asia-africa.md) 和 [欧洲、海岛、美洲与新西兰扩展](docs/experience-expansion-europe-islands-americas.md)。来源检查只验证页面可访问及变更，不会自动把估算改成官方价。供应商未包含的额外门票等仍应核对方案排除项，例如卧佛寺按摩需另选寺院门票。重建脚本仅重建人工核验快照，不代表重新联网核价。

## 后续上线工作

当前没有账号同步、在线支付或公网部署。多设备共享可先通过 JSON 导入导出实现。正式上线应确定供应商授权、部署运行环境、报价缓存期限、更多城市的事实采样流程，再增加用户账号和同步存储。不要将当前估算库宣传为实时预订价格库。
